One hill, five ways to budget an agent team

Five agents climb the same hill-climbing exercise under five budget regimes. Every regime spends the same 100k tokens per window. We watch how long the climb takes, how many tokens expire unused, and how often an agent is cut off mid-task.

Illustrative simulation. Synthetic demand and a toy progress model, built to preview the real demo. These are not measured results.
What stays fixed

The test bench

The hill

Speed up a sparse linear solver

Score is the speedup over a reference solver. Summit: 2.0×. Each step means planning an idea, coding it, scoring it and reviewing it. Gains shrink near the top.

The team

Five roles, fresh memory

Planner, Researcher, Coder, Evaluator, Reviewer. Each scenario restarts the agents with empty memory on the same exercise and the same random draws (seed).

The clock

Budget windows

One window is one budget refresh. Unused tokens expire at the refresh. The org issues 100k tokens per window in every scenario, up to 40 windows.

What we measure

Four numbers

Windows to summit, tokens expired, interruptions (an agent runs out mid-task and loses a quarter of that work), and tokens moved by Rebbi.

Where the real version runs

Test bench candidates

We searched for ready-made environments. None meters per-agent token budgets out of the box, so the budget layer is ours either way. The pick below reuses what we already built for HW8.

Nanda Town + one AlgoTune task

Recommended

Nanda Town already runs Rebbi as an MCP plugin (PR #360). AlgoTune gives the hill: 154 tasks, each with a reference solver, a correctness check and a timed speedup score. Pick two sibling tasks for Exercise A and B.

MultiAgentBench (MARBLE)

Good for roles

Built for multi-agent teams, with milestone-based scoring and star, chain, tree and graph coordination. Milestones map to our flags. Its tasks are less of a smooth climb.

MLE-bench

Too heavy for class

Kaggle competitions with bronze, silver and gold thresholds: a natural hill. One run needs hours and a GPU, so five scenarios with repeats would not fit our time or credits.

Our HW7 dependency audit

Fallback

Already scripted, verified by an answer key, 105 runs logged. It is pass or fail, so there is no climb to draw, but it can stand in if AlgoTune setup slips.

From preview to real runs

Build plan

Bench

  • Wrap two AlgoTune tasks as Town jobs with a score per window
  • Five role prompts, memory wiped per run
  • Window clock: refill budgets every N model calls

Budget layer

  • Equal and manager modes (scenarios 1, 2)
  • Shareable % per agent in config/scenario.toml (3)
  • Usage history to suggest budgets and shareable % (3b)
  • Agent-set shareable %, interest claims, debt limit (4)

Evidence

  • Same four metrics, 3+ seeds per scenario
  • Ledger check after every run (rebbi check)
  • This page reads the real results.csv in place of the toy model
Toy model: each agent's demand per window follows its role and the climb phase (explore, build, polish) with random noise and spikes. Unmet work carries over. Team progress per window is a weighted geometric mean of how fully each agent was served, so one starved agent slows everyone. Rebbi lends only from the shareable part of each budget and only what the lender is not using this window.
